# CDDA 0.I-1 / FP3D：V5 整车轮廓重构实施记录

日期：2026-11-08。基于用户从正面、背面展示的红色车 V4 截图，以及此前的 [车辆 3D 设计说明](FP3D_VEHICLE_VISUAL_DESIGN.md) 第 P2 阶段。**V5 已修改本地源码和 Windows 独立运行包，但尚未在用户截图同一现场完成游戏内人工视觉验收**。

## V4 根因

旧 `fp3d_vehicle_renderer.cpp` 的 `body_shell()` 按每个 CDDA 安装格绘制：每块车架一层地板，每个侧围一块垂直红盒、每块车顶一片方板，全部同时调用 `one_part()` 补充零件。车窗、车门、后备厢、发动机会相互堆叠，车头车尾用同一思路生成，缺少汽车纵向轮廓。结果就是用户看到的“红色平台 + 几排悬空方框”，只改高度解决不了。

## V5 直接实现的改变

1. **整车轴向**：继续使用原版 `vehicle_part::mount` 局部 X/Y 与每车唯一刚性根节点；+X 是车头，-X 是车尾，左右为局部 Z。避免读取原版格子取整的 `precalc` 顶点。
2. **提取原生轮廓**：新增 `silhouette`、`build_silhouette()`，从真实 `frame` 和未破损 `roof` 零件求纵向 `x_min/x_max`、宽度、车顶范围、实际车轮所在行、正常/破损窗和开门状态。不同长度/轮廓决定 SUV/旅行车、轿车、掀背、皮卡或厢式车的基本截面。
3. **不再按每个 roof/mount 绘制完整方盒**：新增 `draw_closed_silhouette()`，车顶由相邻仍存在的屋顶安装行合并成一个连续车顶段，真实缺损才切断。车架每个纵向行只有一层低底盘，不再被每个电子设备叠加高盒。
4. **区分车头与车尾**：车头（+X）绘制连续倾斜机盖、格栅、保险杠、前灯；车尾（-X）绘制后保险杠、尾灯，以及 sedan/hatchback 的后备厢斜顶或 SUV/旅行车的尾门。皮卡的货厢保持敞开，不补假轿车顶。
5. **车门和侧窗合并外壳**：关闭的真实车门是侧围连续漆面中的一段，另有门缝和门把手，不再是竖着的独立红盒；只有 `part.open` 才保留铰链旋转模型。侧面上半部分的车漆或玻璃贴合本体外缘和向内收窄的车顶边缘，并带 A/B/C 柱结构。
6. **整片倾斜挡风玻璃**：单车只生成一个与前机盖、车顶相连的前窗区域，半透明阶段由 `draw_closed_silhouette_glass()` 生成；依据原版 `windshield` 是否存在、破损决定是否画玻璃。侧窗同样读取真实本体门窗、开合/破损状态，不会从原本已经坏掉的零件变出完整玻璃。
7. **轮胎仍独立**：现有厚轮胎、轮拱与轮毂保留，车厢的 1.36 倍纵向高度调整不施加给轮胎，避免轮胎拉长。开式 DIY 车辆、单车、过度拆毁残骸仍走 `one_part()` 模块路线。
8. **贴图**：延续从当前玩家选中图块包的 `vp_*` 提取车漆主色；机盖、车顶主体采用统一车漆，避免把原版 2D 自带伪立体阴影延展到巨大垂直立面。车内不再被顶层红色盒子和大型仪表方块填满。

## 原版车辆真实结构对照

读取本地 `data/json/vehicles/cars.json` 中原版车辆定义：

| 车辆 ID | 安装格 | V5 轮廓 | 原版车顶 X | 下部 X |
|---|---:|---|---|---|
| `4x4_car_abstract` | 29 | SUV／旅行车 | -3..0 | -3..2 |
| `beetle` | 16 | 掀背车 | 0..0 | -1..2 |
| `car_abstract_no_items_1_missing_wheel` | 24 | 旅行车（缺轮子） | -2..0 | -3..2 |

## 修改位置和验证

- **本次唯一车辆源码**：`src/fp3d_vehicle_renderer.cpp`；保留现有 `src/fp3d_snapshot.cpp`、`src/fp3d_materials.cpp` 的 P0~V4 数据与材质处理，不回写原版游戏的 `vehicle.cpp`、`map.cpp`、JSON、玩家存档。
- 工作区增量操作脚本：`qa/apply_vehicle_v5_silhouette.py`、`qa/apply_vehicle_v5_render_passes.py`、`qa/refine_vehicle_v5_silhouette.py`。
- 离线检查：`qa/validate_vehicle_v5_silhouette.py`；结果 `qa/vehicle-v5-silhouette-validation.json`，原版 4 个车型安装点和纵向轮廓检查通过；12 个角度、3 个支点刚性变换误差约 `8.88e-16`。
- Windows 编译目标 `cataclysm-tiles`，CMake/Ninja **通过**；单独 EXE 路径 `runtime/modern-vehicles-silhouette-v5/cataclysm-tiles.exe`。
- 独立 V5 运行包的 49 个 DLL 使用**硬链接**复用旧版文件，避免多拷贝造成磁盘占用；V4 和正常存档仍保留。

## 尚未完成／验收标准

- **尚无用户截图中同一辆红车的 V5 现场画面**，不能声称已经与真实车辆外观匹配。
- V5 是通用程序化低多边形车壳，不是汽车建模软件生成的真实品牌 OBJ；每一款车型独立细节、后视镜、轮胎转动、复杂撞击变形、实际驾驶坐姿相机和物理交互仍属后续工作。
- 对下次反馈，请从同一辆车的正面、背面、侧面、斜侧面提供照片，着重确认：前保险杠、左右车灯、连续机盖、A/B/C 柱、车顶、尾门是否连接；门是否嵌入侧围；轮胎轮拱与底盘是否错位；破损车辆是否出现虚假的完整车身。
- 未提交或推送 GitHub；未覆盖存档或把第三方不死人贴图包上传仓库。
