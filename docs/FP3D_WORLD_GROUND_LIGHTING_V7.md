# CDDA 3D — 地面物品、血迹、植物的世界光照统一（v7b）

更新日期：2026-11-08

## 问题

黑夜或昏暗雨天时，真实 3D 路面已被太阳/昼夜/Photon 阴影处理，但血迹、掉落物和植物仍呈异常鲜亮的独立贴图。经过源代码检查，问题并不是它们在后处理之后绘制，而是原生场景绘制阶段故意关闭 GL_LIGHTING，导致它们在进入 Photon HDR 与阴影处理前已具有不合理的固定亮度。

## 已修改

- `src/fp3d_scene.cpp`：地面血迹 `$blood:` 图层不再 `glDisable(GL_LIGHTING)`。其地板 `floor()` 已有竖直向上的正常法线，和相同位置下方的原始地板使用同一套 `GL_LIGHT0`、环境光、日照强度与场景深度阴影。继续保留透明混合、深度测试和不写深度，避免血迹漂浮或穿墙。
- 场景掉落物和人物/怪物 2D 精灵：世界空间绘制循环保持 `GL_LIGHTING`，并在代表实体的 billboard `quad` 上设置向上法线。这个视觉代理保证人物旋转视角时不会让原本同一件物品因为纸片朝向改变而忽明忽暗；依旧受实际场景深度、透明遮挡和全局环境光影响。**这不是新增动态点光源。**
- 草地和交叉植被：移除无灯光的切图路径，赋予稳定上法线；夜间与地面一起变暗。
- 目标选中时的白色轮廓属于交互 UI，仍以不受照明影响的边线显示。玩家手持物是独立渲染路径，没有纳入本次世界光照衰减；原有窑内真实发光火焰也仍以自发光方式绘制。
- 仅在隔离 QA 抓帧时可用 `CDDA_FP3D_QA_DARK_LIGHT=1` + `CDDA_FP3D_CAPTURE_FRAME=1`，把**渲染光照输入**模拟为近似夜晚，但保留原地图、天气、时间、相机、人物、存档不变；正常游戏没有启用此标记。

## 已完成验证

- Windows UCRT64 `ENABLE_FP3D=ON` 项目编译/链接返回 0，含 `fp3d_scene.cpp.obj` 和游戏 EXE。
- 原有 OpenGL 4.6 / Photon 1.4 GLSL smoke、HDR、太阳阴影比较、60 次目标尺寸改变、直接 final.fsh 和无效 GLSL 安全回退均通过；太阳光体积/SSR/车辆几何静态回归未失败。
- 真正 CDDA 3D `ShaderDaylightLab` 游戏 Photon 1.4 抓帧：相同相机/4 辆车辆/156 个可见部件/30 件家具阴影体；无 OpenGL 读回错误。
- `qa/_verify_worldground_nightlighting_v7b.py` 在同一测试场景对比日间与 QA-only 暗世界光照：地面红色图层样本约 35,004 像素的平均 R 通道由 104.514 降至 38.442（比值 0.3678），证明物品/地面标记现在受环境照明变化影响。
- 截图在 `qa/ground-light-v7b-sunlit.png`、`qa/ground-light-v7b-dark_world_qa.png`，预览 `qa/ground-light-v7b-comparison-preview.jpg`。
- QA 光影选择和质量选项在完成抓帧后均逐字节还原；没有修改真实游戏时间、天气或玩家存档。

## 限制与后续

这次修复了场景对象是否参与**现有**世界光照和太阳阴影。真实火焰、闪光灯、街灯等**照亮附近其他物品**所需的局部动态点光源、衰减、独立小范围阴影和夜间自动曝光还未完整实现。自发光火焰自身不该像地上血迹那样随黑夜变黑。不同贴图包的特殊粒子/火焰仍需用户实际夜间场景检查。

新版 exe：`runtime/modern-3d-shaderpacks/cataclysm-tiles-ground-worldlight-v7b.exe`。根目录 `启动3D操作修复验证.cmd` 指向此程序；保留旧 EXE 与存档。本次未推送 GitHub。
