# P2 前置审查：只读地图快照

2026-10-26。依据当前固定的 0.I-1 本地源码。P0/P1 闸门通过后已开始实现并首次构建预览；本报告保留接口审查依据，P2 尚未完成专项验收。

## 采样与坐标

- `src/game.cpp` 的 `game::draw()`（当前约 4171 行）在 `draw_ter()` 前先调用 `build_map_cache()`、`update_visibility_cache()`。快照应在同一游戏线程、这些缓存已更新后取得；不能在 compositor 的每帧空闲刷新中任意重建地图缓存。
- `src/map.h:1753/1757` 提供 `get_abs(tripoint_bub_ms)` / `get_bub(tripoint_abs_ms)`，`1761` 提供边界检查。必须保留类型区分，不能将屏幕瓦片坐标或相机插值值作为地图坐标。
- `src/map.h:884` 提供只读 terrain ID；家具使用同文件的 `furn()`。采样只复制 ID、语义字段、坐标和可见性，不保留 map/submap、实体或数据定义的裸指针。
- 初期限定玩家当前 z 层和固定局部半径；超出已加载边界立即排除，不为渲染触发地图生成或加载。
- 具体采样点已设在 `game::draw()` 的 `wnoutrefresh(w_terrain)` 之后；Tiles 实际绘制经过该刷新路径，届时原版已准备地图记忆缓存并记录可见地形。3D 不自行调用 `prepare_map_memory_region()` 扩大准备区；`map_memory::get_submap()`（428 行起）对缓存外位置返回空子图，保守视为未知。
- `cata_tiles.cpp` 约 1385 行还将当前可见区域限制在玩家坐标对 SEEX/SEEY 的余数起点及 `(MAPSIZE-1)*SEEX/SEEY` 范围。不能把 `inbounds()` 范围内的所有 visibility cache 条目都当成当前有效的可见格子；应复制原版这层边界限制。

## 可见性必须沿用原版

`src/map.h` 对 `pl_sees()` 的注释写着“不检查光照”，但 `src/lightmap.cpp:850` 的实际实现会检查 `apparent_light`、角色视觉阈值及特殊视觉。因此不能仅凭头文件注释推断规则。

更直接的依据是现有 2D 路径：`src/cata_tiles.cpp:1360` 读取 visibility variables；约 1551 行读取当前层的 `visibility_cache[x][y]`，随后通过 `map::get_visibility()` 判断视觉效果。`cata_tiles::would_apply_vision_effects()`（3141 行）只把 `visibility_type::CLEAR` 视为可正常绘制当前细节。

拟定的保守初版策略：

1. 只有原版判定为 CLEAR 的格子才读取当前地形/家具 ID。其他格子先查询角色已记忆的信息，不读取实时 ID 来“填充”记忆。
2. `avatar::get_memorized_tile()` 返回 `memorized_tile`；`src/map_memory.h:22` 起可读已记忆的 terrain/decor ID、方向、subtile。记忆几何使用记忆内容；门在视线外开关时，不能更新成实时门状态。
3. 完全未知格子不生成透露结构的信息。不得根据隐藏邻格的实时地形决定墙面开口、邻接材质或剔面，否则会间接泄密。
4. P2 首版只显示静态地形/家具及玩家位置，不加入怪物、物品、车辆或 NPC。后续动态实体须另做角色感知过滤；原版 `draw_critter_at()`（约 4045 行）还调用 `you.sees(here, critter)`，并处理特殊视觉，不能用格子可见替代实体可见。

上述 CLEAR 策略可能比原版更保守（例如特殊视觉/低光效果的表现），允许暂时少画，但必须明确报告，不以显示更多内容来补偿。

地形分类可使用已复制 ID 对应的静态 `ter_t` 定义：`mapdata.h:653/654` 的 open/close 状态变换 ID、`has_flag()` 和透明属性。记忆格的分类只能基于记忆 ID；不得使用实时 `map::is_outside()`、当前门状态或隐藏邻居信息来补充记忆几何。家具记忆使用 `get_dec_id()`，需要区分家具与车辆等装饰 ID，不能一概当成当前家具。

## 验证设计

P2 实现前应为下列行为建立有意义的自动测试，并补实机对照：

- 已加载地图的 bub→abs→bub 往返，跨 submap 后绝对坐标不漂移。
- 同一场景开门前后可见集合变化与原版一致；门后怪物/物品不能进入快照。
- 隐藏格子改变门状态后，记忆快照保持旧状态，重新可见时更新。
- 夜晚、封闭房间、烟雾及地下室中，不复制不可感知的实时内容。
- 空闲相机与快照刷新前后，角色坐标、行动点、游戏时间及存档关键字段不变。

渲染模块只接收拥有自身数据的快照。输入动作和游戏状态写入不属于该模块。现有 P0/P1 未完成的实机回归继续保留在持续执行记录中。

`tests/fp3d_snapshot_test.cpp` 三个用例已通过，共 89 项断言，日志 `qa/0i1/p2-snapshot-tests.log`：
