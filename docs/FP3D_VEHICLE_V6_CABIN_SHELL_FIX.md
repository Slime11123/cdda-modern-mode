# CDDA FP3D：V6 车内座椅与连续车壳修复

日期：2026-11-08。接续 [V5 整车外形重构](FP3D_VEHICLE_V5_SILHOUETTE.md)，根据用户 3D 游戏截图（正面及侧面，车身有大洞、座椅缺失、车顶上方有深色贴图）修复程序化封闭汽车渲染。

## 已核实的根因

1. **座椅实际存在，却完全没有渲染。** V5 的 `geometry()` 封闭汽车分支调用 `draw_closed_silhouette()` 后，遍历车辆零件时只保留 `role::light` 和 `role::door && part.open`。原版 CDDA 的 `seat`、`reclining_seat`、`seat_back` 都通过 `SEAT` 标记被快照正确分类，但 V5 在这个分支把它们遗漏了。
2. **侧围连接条件过严。** V5 的车身逐纵向行绘制时，侧格即使有完整车架，只要缺少该格自己的 `body / door / window / roof` 标记，整段侧围就直接跳过。部分正常安装格因此留下视觉大洞。这里须尊重真正拆除的门/受损面板，不能无条件补墙。
3. **前后舱缺少垂直封口。** V5 虽然绘制了机盖倾面、前保险杠、尾部构造，但机盖下方到前下围板、后备箱尾部到后底盘之间没有足够的连接面，能直接看到另一侧的环境。
4. **车灯重复放大。** V5 既在车头绘制通用大块米色灯，又将真实 `role::light` 当作普通外置长方体单独绘制，造成两套大灯叠加。

## V6 已直接修改的源码

唯一新增修改的车辆源码：`src/fp3d_vehicle_renderer.cpp`。其余 V5 已完成的原版快照、材质切换、刚性坐标、车门开合、损坏及轮胎绘制继续沿用；不更改 `vehicle.cpp`、`map.cpp`、车辆存档或驾驶物理。

| 模块 | V6 代码实现 | 原版约束 |
|---|---|---|
| 真实车内座椅 | 新增 `cabin_seat()`，按 `part.mount_x/mount_y` 绘制支架、坐垫、靠背、侧边、可选头枕；靠背朝车辆后方（本地 -X），坐垫顶部继续可读取当前图块包的真实 `vp_*` 图块 | 所有带 `SEAT` 的真实安装零件都绘制，没装座椅不生成；车顶损坏也不无故隐藏后座 |
| 驾驶区域 | 新增 `cabin_controls()`，原版驾驶控制零件绘制简化方向盘，`dashboard` 提供低矮的深色仪表板 | 仅按真正安装的控制零件绘制，不额外生成驾驶模块 |
| 侧围补缝 | `has_native_side_skin()`、`should_bridge_side_skin()`：若完整车架侧格缺少外部分类，但前后**相邻两格**都有真实外板，填补这一格 | 不为破损车架、破损围板、真实打开的门恢复完整外壳 |
| 受损车壳 | 原本损坏的侧围仅留较低、较短残片，不套完好金属板；轮拱保持开口 | 原版破损、拆除状态为唯一权威 |
| 前后舱连接 | 新增机盖下前端封口、非皮卡车辆尾部下围板，修复外视角可穿过车头/车尾看到地面的问题 | 前后仍保持原版车头 +X、车尾 -X，皮卡保持正常敞开货厢 |
| 前侧翼子板 | 用与 V5 风挡下缘连接的薄肩板衔接 A 柱和前机盖，补充之前悬空玻璃下的缺口 | 停在轮拱上方，不遮挡真实圆轮胎 |
| 车灯 | 不再画固定大块灯加重复真实零件；读取实际 `role::light` 的车头灯/尾灯零件位置，将小型灯罩嵌入车身端面，坏灯用深色 | 灯缺失或破损时不会凭空发亮 |
| 底盘格缝 | 连续车架行在长度方向有少量交叠，避免每格 `0.99` 长度造成近景可见裂缝 | 不改变原版挂点、道路地形或者碰撞体 |

## 原版车辆定义及测试

用项目中的原版 `data/json/vehicleparts` 和 `data/json/vehicles` 核实：
- `seat` 与继承它的 `reclining_seat`、`seat_back` 均具有 `SEAT`；`trunk` 并不具有 `SEAT`，不会被误画成座椅。
- `4x4_car_abstract`：2 个原版座椅；`beetle`：2 个；`car_abstract_no_items_1_missing_wheel`：4 个（2 前 + 2 后）；`pickup`：2 个。
- 在现有纵向缩放 1.36 下，座椅靠背高度约 1.58 个世界单位，车顶高度约 1.93，不会正常状态穿过车顶。
- `qa/validate_vehicle_v6_seats_shell.py` 的 **19 项源码/结构检查全部通过**，结果写到 `qa/vehicle-v6-cabin-shell-validation.json`。
- 独立 Windows `cataclysm-tiles` 构建链接通过，打包的 EXE `--help` 退出码 0、`--jsonverify` 退出码 0，stderr 为空。JSON 命令 stdout 有 4 条测试路径字体缺失的非致命提示（与原来一样）。

## 运行版本

- **V6**：`runtime/modern-vehicles-cabin-v6/cataclysm-tiles.exe`。
- **启动**：项目外层目录的 `启动3D操作修复验证.cmd` 或 `启动车辆3D座椅与车壳修复V6.cmd`。
- **V5**：仍保留 `runtime/modern-vehicles-silhouette-v5`，没覆盖以前的 EXE。
- 49 个 DLL 从 V5 使用硬链接，防止复制相同大文件、浪费空间。
- 没有修改或删除用户存档，不推送 GitHub，不上传第三方不死人图块素材。

## 尚未完成的现场验收

**机器编译、静态代码检查和 JSON 校验不代表修复后的 3D 画面已在用户这辆车上验收通过。** 请回到同一位置检查车门关闭/打开、前后排座位是否通过窗户可见、车身两侧是否连续、轮胎是否仍露出、车头尾部是否封住；用户截图里**车顶上方的深色漂浮平面**仍未确认是汽车材质还是地图其他高度层的几何体，本轮未在没有证据的情况下改动非车辆渲染器。

下一步若仍有缝隙，应通过同地点 2D/3D 对照找出对应 `mount` 的原版 `door / windshield / halfboard / roof` 是否损坏、拆除或被遮挡，然后针对该车型进行局部截面与损坏外观修正。
