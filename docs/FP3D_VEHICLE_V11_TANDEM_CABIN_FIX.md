# V11：电动双座机舱式摩托车（两轮封闭座舱）模型修复

日期：2026-11-08，针对用户提供的 V10 3D 前侧、左侧截图（截图 UI 显示 `电动双座机舱式摩托车`），发现此前 V5–V10 一直将它当四轮轿车套用车壳；在用户的 3D 截图中，这导致后半部侧板断开、车轮出现在座舱里，以及前部大块灯壳。

## 实际原版数据诊断

用户图中车辆是官方 CDDA 0.I-1 `Electric Tandem Cabin Motorcycle`，在 `data/json/vehicles/cars.json` 中以两款实例存在：

- `scompact_tandem_electric_2wheel_stow`
- `scompact_tandem_electric_2wheel_hboard`

它们继承 `scompact_tandem_abstract` 的**三格宽车架、两块车顶、前后两张座椅、左右车门、左右半隔板**，但真正轮胎是 `(x=1,y=0)` 和 `(x=-2,y=0)` 的**两只中置 `wheel_motorbike`**。这不同于四轮 `scompact_tandem_electric_stow`；不能按四轮侧车胎/侧轮眉推算。

旧模型的问题是：`wheel()` 的轮胎半径 `.34`，顶部达到约 `.692` 本地单位，而底板顶部只有 `.35`，导致中置摩托车胎上半部分裸露在座舱中；另一个问题是 `halfboard` 的外壳只到 `.59`，与车窗下边沿 `.852` 相差约 `.26`，留下一个横贯后侧的缺口。V10 虽然补了柱子，但没有针对摩托车更改轮罩和后半板。

## 本次实际修改

**生产源码仅修改** `src/fp3d_vehicle_renderer.cpp`，没有修改原版车辆 JSON、驾驶、AI、碰撞、载具损伤、瞄准交互、存档。

1. 增加 `shell_profile::centerline_motorcycle_cabin`。根据**真实安装部件**而非译名自动识别：封闭车架有至少 1 个屋顶、至少 5 个车架零件，并且轮胎总数恰好为 2、都使用 `motorbike` 部件，且都位于同一 Y 安装列。拆/装轮胎后会重新依据快照计算，普通四轮车不会被错误识别。
2. 对识别出的封闭双轮车，将后部原生 `halfboard` 侧围从本地高度 `.59` 补到 `.82`，刚好连接车窗的 `.852` 下框；保持 V9 的高处玻璃和 V10 的实际车柱，不重新生成整块高耸红墙。
3. 根据两只原生摩托车轮的真实安装 X/Y 位置，在对应的前后胎位构造低矮轮罩，顶部 `.78`、底部 `.34`。这能遮挡穿入驾驶舱内部的上半轮胎，同时留下底盘下真实可见的圆形轮胎。破损轮罩仅延伸至 `.62`。
4. 中置摩托轮不再被虚假向车身侧面偏移 `.10`，而是在实际车身中心线上绘制，保持轮间距和原版转角坐标。
5. 针对前挡风玻璃所在、原版只有 `frame + windshield` 的最前一行，将过低的侧槛连接到前翼子板/挡风玻璃底座，避免前车架仍在空气中结束。
6. 前后灯壳沿用原生安装格数量，但仅对两轮座舱车型缩小灯面尺寸，让灯嵌入车鼻而非突出成大块米色立方体。
7. 其他普通四轮车、开放式摩托车、自行车继续走原来的车壳或开放式轮框路径。

## 测试

- 完整 Windows C++ `cataclysm-tiles` CMake/Ninja 编译链接成功（退出码 0）。
- `qa/validate_vehicle_v11_native_2wheel.py`、`qa/vehicle-v11-native-centerline-validation.json` 通过。解析官方 `cars.json` 的 `copy-from` 布局：4 种单双配置都识别为两只中置 `wheel_motorbike`，两种四轮 `Supercompact Tandem Car` 对照模型不匹配；120 次安装点旋转回转检查通过。
- 独立测试 EXE `runtime/modern-vehicle-centerline-v11/cataclysm-tiles.exe`，与 V10 共用 49 个 DLL 的硬链接副本（实际磁盘占用不重复），旧 V10 保留。
- 运行入口在工作区根目录：`启动双轮座舱车V11测试.cmd` 或 `Start-TandemCabin-V11.cmd`。
- `qa/vehicle-v11-help.log` 和 `qa/vehicle-v11-jsonverify.log` 保存启动/原版 JSON 校验结果。

## 仍需要真实游戏画面验收

该补丁只针对上述**已确认的特殊两轮封闭车**，并未给所有载具添加量身定制的高精度独立网格。**本机尚未自动在用户截图的实际地图位置/相机角度运行游戏拍照**，不能仅凭 C++ 编译和原版 JSON 通过宣称「车壳已全部补齐」。

建议玩家使用 V11 回到同一辆红色双轮座舱车，从 3D 左侧、斜前方、车内再次查看：后侧原先大缺口应被下围板连接，后轮不应从座位侧面凸出，头灯不应再是巨大方砖。任何剩余问题可通过同一角度截图定位局部网格；下一步建议从按车型轮廓模板/三角形结构建模替换当前通用立方体拼接算法，避免反复叠补几何。
