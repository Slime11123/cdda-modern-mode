# 多楼层移动卡顿修复

日期：2026-10-27。修复基线 `a67e92c4`。默认交付目录 `runtime/movement-perf`。

## 定位

用户实机日志 `runtime/0i1/user/config/debug.log` 中，每次移动的快照采集约 78–81 ms；移动过程中新增材质槽也很频繁。原实现对约 10 万格反复查询角色视野，外立面检查再重复查询相邻格；每次查询还重复计算相同的装备/变异视力阈值。空格也执行 NPC 扫描和物品显示条件检查。图集每追加一个槽都会增加全局版本号，导致所有静态区域缓存被清除。

上次固定场景绘制基准没有体现这些移动开销。本次以连续原版移动和采集耗时为主要验证依据，不用静止绘制吞吐代替移动体验。

## 修复

- 每次同步采集只计算一次原版视力阈值、感知距离和超感知参数。原版三维视线/相机缓存先排除明确不可见格，其余使用 `map::apparent_light_helper()` 的原版光照和遮挡结果，保留光源、相机和超感知分支。
- 结果保存于本次采集的临时字节表，包含一格邻接边界。外立面判断复用它，不再对同一邻格反复计算视野。该表来自三维原版缓存，不是 2D 视口 mask，不要求已有探索记录。
- 仅遍历实际生物位置建立临时索引，在这些位置调用原版优先生物查询；保留原版逐生物感知检查。避免对十万空格逐个扫描 NPC。
- 先检查实际物品数量，只有存在物品时才检查遮盖场和原版容器规则。隐藏格仍只读取记忆。
- 追加材质槽时保留现有区域缓存，因为旧材质坐标没有变化。切换图块、季节、图集重置或释放时仍完整失效；新增地形和邻接变化仍刷新相关区域。

采样半径仍为 60，默认上 4 / 下 2 层、120° 水平视角均保持；没有通过缩短视距或减少楼层来提速。原版行动与世界规则未修改。
