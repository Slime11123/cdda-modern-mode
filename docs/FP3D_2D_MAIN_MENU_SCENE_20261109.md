# CDDA3D 主菜单：原生 2D 游戏画面背景（2026-11-09）

## 当前架构

主菜单 UI 保持原样，标题、左侧按钮、版本号和底部提示均不移除。背景不再从贴图包手工组装房屋、车辆与 NPC。

- 源头：玩家在正常 2D 游戏过程中，由 CDDA 自身地图与车辆、NPC 和怪物渲染器输出的画面。
- 录制：`src/fp3d_menu_native_capture.inc` 以最高约 1.5 帧/秒采样地图窗口，在内存中保留最近 48 帧；只在真实 2D 游戏地图被绘制时采样，不采集主菜单或设置面板。
- 缓存：返回主菜单时写入 `runtime/0i1/config/native_menu_capture/frame_*.bmp`；再次启动时读取本地缓存。素材仅留在玩家电脑，不上传。
- 回放：按真实录制时间间隔播放一次，最后一帧保持静止，不重放固定的战斗动画。
- 首次启动：如果尚无原生录制内容，使用用户之前提供的真实 2D 游戏截图作初始底图（仅一帧）。
- 仍保留常用游戏版本、存档、当前选择的贴图包以及 2D/3D 切换。

## 说明与限制

这不是在主菜单里新开一个带 AI 的游戏世界。主菜单启动时 CDDA 尚未准备地图、世界和 NPC 回合数据，直接在该阶段调用 `map::generate` 或 `game::do_turn` 会触碰全局 `game`、`MAPBUFFER`、`overmap_buffer` 和世界状态，存在污染存档的风险。因此背景使用**原版实际游戏输出**录制，而不是假装调用原生车辆函数却继续手工拼接。

NPC 装备、近战、远程射击与驾驶只会在这些行为确实发生于录制的游戏画面时显示。普通游玩几分钟之后，主菜单可自动回放最近的真实场景。若需开机即有多段自动演出，下一阶段必须实现隔离的专用演示世界进程；不能把正常玩家存档当演示世界。

## 调试与验收

1. 新启动：标题、原版按钮正常，初始真实游戏截图底图显示。
2. 进入 2D 游戏并走动约 10–30 秒，返回标题：最近的真实地图画面连续播放，最后停住，不循环复活 NPC。
3. 驾驶或真实 NPC 交战后返回标题：相应游戏动作只有被实际录制时才会出现。
4. 关闭重启：从缓存回放真实画面；修改窗口尺寸时不会产生手工车辆拼接错误。
5. 3D 模式不被录像采样；整个流程不自动载入、改写或创建存档。
