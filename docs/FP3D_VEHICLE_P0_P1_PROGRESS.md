## 本轮实际完成

| 原计划 | 落地 | 状态与边界 |
|---|---|---|
| P0-V 所有已加载 `vehicle` 枚举 | `fp3d_snapshot::capture()` 从 `map::get_vehicles()` 枚举，按本次采集去重；复制车辆位置、旋转支点、真实零件 ID 和安装位置；不按玩家驾驶/损坏程度筛选车辆 | 已编译。尚未完成所有车型的真实存档覆盖验收 |
| P0-V 感知过滤 | 对每个真实零件利用原版 `mount_to_tripoint_abs` 取得逻辑占用格，仅作原生可见性判定；仅复制通过 native perception 的零件 | 不绘制墙后尚未感知的零件，不保存 `vehicle*` 裸指针 |
| P1-V 刚性车身 | `fp3d_vehicle_renderer.cpp` 在车辆局部 `mount - pivot` 下生成车架、轮子、车门、窗、车顶、座椅、引擎、货箱及未知件中性模块，外部只对整车根应用一次旋转/平移 | C++ 编译已通过。0°/15°/45°/90°/180°/270° 等连续变换的数学测试通过；原版 2D 占用格校准与实机驾驶验收仍缺 |
| P1-V 图块包 | `fp3d_materials::prepare` 按可见车辆部件去重请求，使用当前选中的 tileset 读取 `vp_<id>`、原版 vpart looks_like；UV 仅作为顶部贴花，侧面简化色调，缺图块降级为中性面并记录缺失 | **只是基础图块适配**：朝向/变体、开门与破损图块、透明窗和精细侧面尚未完成 |
| P1-V 动态与缓存 | 车辆独立于静态地形块绘制，GL 显示列表按局部部件结构、部件开关和受损状态签名缓存；只改变根位置/角度不会因其变化单独重新生成车体网格 | 已实现基础拓扑缓存，限制缓存条数 160，尚无更复杂 LRU/性能验收 |
| P0-V 可检查覆盖率 | `scene_snapshot` 记录已枚举车辆数、可见部件数；`fp3d_scene::draw_statistics` 记录已加载/可见车辆数和部件数 | 提供调试/后续 QA 数据，不声称当前场景的覆盖矩阵全部通过 |

## 本地真实贴图源审核

- 本机的 `MSX++UnDeadPeopleEdition` 当前配置包含 **752 个车辆 `vp_*` 贴图 ID**；原版 `data/json/vehicleparts` 扫描有 **350 个具备文字 ID 的车辆部件定义**。
- 其中 289 种在该包存在精确同名 `vp_*`，额外 12 种存在单级 `looks_like` 贴图匹配；其他部件仍有运行时多级继承与中性部件降级。**这不是所有车型纹理均已完成的证明**。
- 不将第三方图块包图片复制到仓库，材料读取仍通过玩家游戏当前选中的 tileset 进行，未硬编码 UndeadPeople 路径。

## 验证记录

- `qa/validate_vehicle_p0_p1.py`、`qa/vehicle-p0-p1-validation.json`：静态结构检查，使用 10 个非矩形零件坐标、3 个不同支点与 12 个角度，比较任意两零件长度；误差最高约 `1.33e-15`。
- 构建：CMake/Ninja `cataclysm-tiles`，成功。`--help` 成功，`--jsonverify` 成功（若数据路径下字体提醒属于非致命 stdout）。
- 包：`runtime/modern-vehicles-p1`，独立 49 个运行 DLL + 当次编译 EXE，不覆盖旧的 `runtime/modern-fence-wire-v2`。
- 启动：`启动3D操作修复验证.cmd` 和 `Start-Vehicles3D-P1.cmd`。

3. P2-V：独立车型外壳、轮胎侧面正确图块、车门实际铰链/开关动画、真正透明窗、破损变体、受损残壳等仍需继续做；目前是模块灰盒带顶部的同包贴花。
4. P3-V：驾乘视角随座位变换、实际准星与车辆零件交互映射、输入、碰撞边界视觉修正仍未完成；游戏逻辑依旧用原版 CDDA。
5. P4-V：黑暗 LOS/记忆边界、跨层可见性、静态废车与快速行车的性能、图块包切换以及原版 2D/3D 多次往返还未通过实机验收。

## 玩家现场验收建议

先在同一张存档中找城市废车、车库中停车、摩托/自行车和玩家车。以 3D 模式观察静止车身和斜向车，尝试原版操作让车转向，看车架和轮子是否保持相对结构；再比较 2D 可见的实际车辆零件及损伤状态。若有黑屏/分裂/遗漏，保留游戏日志和 2D/3D 同地点截图。
