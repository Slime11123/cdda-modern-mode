## 1. 最终目标与默认约定

在现有 3D 模式中增加以玩家为中心的 3D 俯视模式。F6 在第一人称与俯视之间双向切换；首次进入 3D 默认第一人称。俯视模式必须使用原版 2D 的玩家感知规则，不能因相机升高或旋转获得额外视野。

| 项目 | 必须实现的行为 |
|---|---|
| F6 | 3D 世界操作状态下切换第一人称／俯视；长按不反复切换；不消耗回合 |
| F5 | 保留模式设置入口；2D 中 F6 暂保留原有设置行为 |
| 右键 | 点击可见地块，在鼠标位置打开与现代 2D 相同的下拉菜单，条目、条件、执行结果一致 |
| 滚轮 | 鼠标在世界视口内时缩放俯视相机；在菜单上时由菜单处理 |
| 中键拖动 | 绕玩家旋转相机；建议首版只改变水平角，固定俯角，松开立即停止 |
| 建筑外 | 可观察建筑外墙、屋顶及整体体量，不默认剖开内部 |
| 建筑内 | 跟随玩家实际楼层展示该层内部；隐藏所属建筑遮挡该层的屋顶、天花板和更高楼层 |
| 遮挡 | 墙、关闭的门、黑暗、楼层与原版感知能力共同决定可见内容，与同状态 2D 一致 |
| 玩家 | 玩家贴图位于其实际地块，脚底对齐地面；随移动、楼层、姿态及时更新 |
| 手持显示 | 不绘制第一人称手部／手持物模型及挥击覆盖层；俯视玩家贴图也默认不叠加手持物外观，保留衣物外观 |

建议初始参数：透视投影、俯角约 60°、距离约 18 个地块，缩放范围约 6–48 个地块；这些是可调参数，以实际模型高度及视口验证为准。再次切换俯视恢复本次会话的角度与缩放，切回第一人称恢复原来的朝向与俯仰。

俯视下移动沿用现代 2D 的世界网格方向，旋转相机不改变按键对应的地图方向；左键沿用现代 2D 行为。此为补全未指定行为的默认约定，实施时在帮助文本中写清。

“整体轮廓”指已知建筑的外部体量，不表示揭露未知建筑背面真实细节。未探索部分保持未知；必要时用不含内部信息的简化体量补齐外观。视觉隐藏屋顶不能改变屋顶实际碰撞、遮光、天气或楼层结构。

## 3. 按顺序实施

### P0：状态拆分与 F6 路由

1. 将“是否使用 3D 渲染”与“3D 相机类型”明确分开。新增第一人称／俯视相机状态，并为俯视提供明确的输入分支，避免用 modern_2d 状态冒充俯视而触发 2D 渲染。
2. 3D 世界状态中优先处理 F6，消费事件后不再打开设置窗口。只响应首次按下，过滤按键重复；同时检查 keycode 与字符输入路径，避免触发两次。
3. 设置、文本输入、弹窗等占用输入时遵守当前窗口优先级，不从后台切换世界视角。
4. 切换时取消拖动、按住动作、待触发攻击和旧目标，更新光标／相对鼠标模式并使场景快照失效，避免旧可见内容闪现一帧。
5. 更新 F5/F6 帮助、提示、按键说明及相关测试；实施完成后同步 AGENTS.md 中原有 F5/F6 行为描述。

完成条件：F6 双向切换稳定，F5 可用，切换不推进世界时间，退出弹窗／失焦后不残留鼠标锁定。

### P1：俯视相机与输入

1. 在相机模块建立独立俯视参数及统一的 view/projection、视口换算接口，供绘制、裁剪、鼠标拾取共享。不得继续假设相机位于玩家眼睛高度。
2. 相机注视点跟随玩家实际位置及楼层；使用已确认位置进行平滑，不用输入意图预测穿墙移动。
3. 滚轮平滑调整距离并限制范围；中键水平拖动改变方位角。切换视角、松键、失焦、打开菜单均应终止拖动。
4. 俯视释放第一人称鼠标锁定；滚轮和中键不得同时触发原来的物品、攻击或其他动作。处理 UI 缩放、高 DPI、窗口缩放和侧栏导致的视口偏移。
5. 将正确相机参数传入深度、阴影、反射等相关通道，防止主画面切换后附加效果仍按第一人称绘制。

完成条件：缩放／旋转围绕玩家稳定进行，不改变其位置、朝向、感知或游戏时间；第一人称回归正常。

### P2：与 2D 一致的感知与记忆

1. 为快照捕获增加明确的感知策略：保留现有第一人称策略，俯视使用原生 2D 感知结果。不要仅靠 OpenGL 深度遮挡模拟 2D 视野。
2. 从玩家实际地块、当前楼层建立原生视野，区分当前可见、仅有记忆、未知。原生特殊感知与黑暗表现也应按 2D 对照处理，不要统一简化成“普通 LOS 通过就可见”。
3. 仅记忆地块按原生地图记忆显示静态信息；不读取背后实时家具变化，不复制隐藏怪物、NPC、物品及动态效果。未知区域不显示真实内容。
4. 过滤发生在快照构建阶段，并覆盖灯光、阴影、反射、轮廓、高亮、悬浮提示和目标候选，防止这些通道泄露隐藏对象。不要因此取消原生 2D 本来允许看到的门缝光照等效果。
5. 旋转／缩放不重算玩家探索范围，不写入额外记忆；移动、开关门、灯光变化、楼层改变后正常刷新。缓存无效时禁止沿用上个视角的可见实体。

完成条件：同一存档、位置、时间和感知状态下，2D 与俯视的地块知识、怪物和物品可见集合一致；允许画法不同。

### P3：建筑外观与楼层剖切

1. 先审查现有 `exterior_only`、ceiling、landscape、楼层快照与建筑信息，定义“当前所属建筑／室内区域”的可靠判定。不能只用一个 is_outside 布尔值或单纯地面连通性决定整片区域剖切。
2. 室外保留已知建筑外壳和屋顶，展示立体轮廓；外壳数据必须与内部内容分离，不得为了完整造型复制未感知室内物品或实体。
3. 室内只展开玩家所属建筑的当前楼层，剔除其遮挡屋顶、天花板及上方楼层；其他建筑保持外观。当前层仍经过 P2 过滤，不能显示整层所有房间。
4. 保留当前层墙体和深度遮挡。近侧墙遮住操作区域时，可采用视觉上的局部降墙或透明处理，但仍使用完整逻辑墙体计算视野，且不可透视显示原本隐藏内容。
5. 处理楼梯、地下室、屋顶、露台、中庭、门口、连体建筑、地下通道和不同高度相邻建筑。穿门或上下楼后同帧更新剖切与拾取层，避免闪出其他楼层内容。
6. 若原生建筑标识不足，先实现稳定的区域归属与缓存失效规则，再继续完整剖切；记录无法准确识别的结构，不得用全地图统一删除 z 高于玩家的几何冒充完成。

完成条件：屋外可辨建筑整体体量；进屋展开所在层；上下楼同步切换；关门房间仍保持原生遮挡，远处建筑不会一起消失。

### P4：地块拾取与复用 2D 下拉菜单

1. 将鼠标坐标换算为世界视口坐标，使用实际俯视相机矩阵生成射线，与当前展示层的可交互地块／表面相交。不能用 2D 屏幕坐标公式，也不能沿用准星中心目标。
2. 屏幕外、UI 区域、未知区域、记忆但当前不可操作区域、不可选外壳应返回无目标。不得穿过可见墙面选中墙后的地板。地块命中规则需覆盖门窗、楼梯、家具及高模型遮挡。
3. 输出真实原生地块坐标，复用 `context_2d_entries()`、`show_dropdown()`、`resolve_2d_choice()`，抽取共享入口以避免复制菜单业务逻辑。
4. 复用原生可见性、距离、路径及动作条件校验；菜单执行前重新确认目标有效。菜单显示及取消不消耗回合，实际动作仍走原生结算。
5. 俯视中的攻击、拾取、交互等统一审查目标来源，不允许残留的第一人称准星目标抢占鼠标目标。

完成条件：同一地块在现代 2D 与俯视显示相同菜单和可用条件；旋转、缩放、调整窗口后仍选中鼠标所指地块。

### P5：玩家贴图与手持隐藏

1. 快照增加或复用玩家角色精灵，使用当前 tileset 的人物、性别／变体及衣物叠层，不用固定替代图。避免把玩家同时作为 NPC 重复绘制。
2. 玩家脚底锚定实际地块中心与实际楼层；选择适合俯角的朝向相机精灵方式，确保高角度下不会薄成一条线。绘制尺寸不随旋转异常变化。
3. 俯视关闭第一人称手持物绘制、挥击覆盖层和不适用的准星；不改变真实装备、攻击效果及原生照明。
4. 处理蹲伏、骑乘和乘车；玩家展示位置使用已确认位置，不能把显示插值位置用于交互距离和游戏判定。
5. 切回第一人称恢复其手持物与 HUD，隐藏俯视玩家贴图，避免看到自己身体叠在镜头前。

完成条件：玩家贴图总在正确地块和楼层；无残留手持画面，装备与战斗效果不变。
