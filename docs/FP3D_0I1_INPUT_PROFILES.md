# 2D / 3D 操作分离

2026-10-27，按用户要求为后续 3D 按键建立独立入口。

## 游戏内使用

- F5 切换 2D / 3D 画面及操作方式。
- 2D 保留原版动作和按键配置，原版按键菜单入口保持。
- 3D 默认 W 前进、S 后退、A 左移、D 右移，按镜头方向换算成原版格子动作。
- 3D 中按 F6，或打开原版按键帮助，进入“2D / 3D 操作设置”。选 1 查看原版配置；选 2 查看、修改独立 3D 按键。3D 的“+”局部绑定写入 FP3D 类别，通过原版设置界面保存。
- 背包等菜单仍使用各自的原版操作；失去焦点或退出 3D 后不拦截 3D 移动键。尚未单独定义的普通操作继续使用原版入口，本次没有改键到 E、鼠标战斗等新行为。

## 代码入口

`fp3d_input` 拥有独立 `FP3D` 输入类别、命令列表、默认键和命令到原版动作的转换。默认绑定位于 `data/raw/keybindings.json`，与 `DEFAULTMODE` 分开。后续增加 3D 动作时，在该列表及转换入口扩展，不再往 SDL 事件层叠加硬编码字母判断。

已移除原来的 SDL 层 WASD 特判及伪键码 -1 通道，改在原版输入上下文收到真实事件后查询 3D 配置；只允许提交当前原版游戏上下文注册过的动作。角色移动、碰撞、安全模式及行动点仍由原版处理，不直接写位置，也不建立额外动作队列。

## 验证与交付

`qa/0i1/input-profiles-final-cpu.log`：22 用例、682 项断言全部通过，包含八方向下的原版动作有效性、2D 配置不受 3D 命令影响、菜单上下文不接管角色移动，以及保存的 3D 改键重新加载后生效且原版 wield 绑定保持。测试只在隔离 QA 用户目录写入临时配置，并在结束时恢复原内容。

首次运行因原版缓存检测到改动后的 keybindings.json 而记录过期数据；原版重建缓存后重新运行，最终退出码 0。没有关闭错误检查或修改缓存实现。

Feature OFF 构建通过，无直接 OpenGL 导入；随后 ON 恢复构建成功。设置菜单的新交互尚未做实体键盘人工复验，不将单元检查写成人工验收。

检测到用户仍在运行旧的默认程序，所以保留该进程，未替换其可执行文件或存档。根目录“启动3D技术验证.cmd”已指向独立 `runtime/input-profiles`；保存退出当前游戏后重新打开即可使用。用户目录仍为 `runtime/0i1/user`，语言和图块配置继续沿用。构建日志及程序哈希见 `input-profiles-final-build.log`、`input-profiles-delivery.json`。
