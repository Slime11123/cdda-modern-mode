# CDDA 第一人称 3D 车辆 V12-A：真实车架拓扑与逐排车身轮廓

日期：2026-11-08。继承 V9 座舱、V10 实体车架与 V11 封闭双轮车修复。

## 本阶段实际实现

本轮修改正式源码 src/fp3d_vehicle_renderer.cpp，**没有更改** CDDA 原版车辆逻辑、JSON、驾驶碰撞、存档、贴图包、车辆安装格、材质缓存或其他光影/UI 源码。

1. **拓扑合法性**：完整封闭车壳必须有连续的原生车架安装行，每行的最左至最右必须实际安装有完好 frame，并且相邻行的车架范围必须连通。遇到缺格、损坏、分离车架，不再将行边界之间填成不存在的底盘与顶棚。
2. **不规则车辆安全退化**：当封闭车壳条件不成立时，使用真实每个零件的模块化 3D 底盘、车门、轮胎、车顶和侧板。旧逻辑中 enclosed=true 但 silhouette=false 时会漏画 frame/body；V12 显式切换 modular.enclosed=false 解决这一漏洞，同时不放大开放式模块车身的高度。
3. **逐排外缘**：native_side_at_row() 以实际原版 frame 行的左右端点计算局部边缘，不再强行让前后车体、灯光、玻璃侧面等全部使用整车全局最大宽度。
4. **逐排顶沿**：native_roof_edge_at_row() 采集每个座舱位置的真实完好车顶安装列，根据当前行的实际车架左右轮廓限制上玻璃边缘，避免侧窗框与外壳脱离。
5. **车头/车尾/玻璃联动**：车头/车尾盖板、保险杠、进气口和灯具按当前原生端部宽度生成；车头引擎盖按真实车顶边缘至前端宽度生成；透明玻璃逐排跟随当前边缘，不改变原版玻璃破损和门开合规则。
6. **V11 特殊车型维持**：两只中置摩托车轮、低矮轮罩与 V10 实体窗柱仍继续工作；既有显示列表缓存和与阴影共用模型的绘制路径保持不变。

## 测试方法、结果与边界

- qa/validate_vehicle_v12_topology.py：通过源代码存在性检查、6 类合成车架场景、原版 5 款车型（4×4 Car、Station Wagon、Microcar、Supercompact Car、Supercompact Tandem Car）的实际 frame 安装表解析；原版五车仍能使用完整座舱。结果 qa/vehicle-v12-topology-validation.json。
- 原 V10 车架、V11 双轮原生车型校验脚本均通过。
- 构建：CMake/Ninja 目标 cataclysm-tiles 完成；编译对象及 EXE 时间戳均晚于 V12 源码。本次编译过程最初遇到一次未附带编译器诊断的 Ninja 失败；随后检查到完整构建退出 0 和已更新的目标文件。构建记录在 qa/vehicle-v12-cmake-*。
- V12 独立运行包：runtime/modern-vehicle-topology-v12/；与 V11 共享 DLL 硬链接，不覆盖主光影程序或 V11。对应 qa/package_vehicle_v12.ps1 做 strip、--help、--jsonverify 校验。
- 启动：项目根目录 启动车辆V12轮廓测试.cmd，基于现有 tools/run-fp3d.ps1，运行前请正常关闭其他 CDDA 进程。
- **本轮未通过真实游戏内同车同角度的肉眼对比验收**。源码+原版 JSON+CLI 启动校验不是车壳已完全不穿模的证明；此轮只覆盖 V12-A 轮廓基础，复杂车门铰链、三角连接面、货箱/修理交互、运行时 FPS 属后续 V12-B / P3-C / P4。
