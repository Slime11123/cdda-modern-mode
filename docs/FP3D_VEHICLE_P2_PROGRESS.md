## 已接入源码的功能

| 项目 | 实现 | 未覆盖边界 |
|---|---|---|
| 原版变体 | 快照新增 `vehicle_part::variant`；材质键 `$vehicle:<id>#<variant>`。按原版 `cata_tiles` 规则依次尝试 `vp_<id>_<variant>`、逐级裁剪下划线变体、`vp_<id>` 与同包 `looks_like`。 | 仍未解析所有原版 subtile（开门/破损）的专用贴图，有些当前包没有专用素材。 |
| 外形朝向 | 门、玻璃与装甲板根据真实车架挂点分布和本地变体选择侧面/前后，并围绕同一局部车辆根节点绘制。 | 非矩形极端结构使用通用推断，仍需 L/T 形和单格车实机验证。 |
| 门状态 | 原版 `part.open` 控制本地铰链约 77° 的静态开门造型；受损门只保留残片。 | 尚无开门连续动画或与原版每一款门铰链方向的精确一致性。 |
| 轮胎 | 真实轮胎按原版车轮部件位置绘制成 16 段圆柱、双面轮毂；细胎/宽胎外观区分，破损轮胎降高、变形；侧向圆盘显示当前贴图包的车轮图块。 | 真实悬挂、轮胎滚动/转向动画和实际车轮尺寸仍需与各车型校准。 |
| 车窗 | 独立外缘窗框 + 后期半透明玻璃，透明玻璃可叠加当前包实际窗图块，破损/打开状态不绘制完整窗格。 | 不是物理真实碎玻璃；与建筑透明层的复杂混合排序未做全面场景验证。 |
| 车架与残骸 | 未破损车架相邻块略重叠；破损改为裸露交叉梁。车顶缺失/破损只按残存真实部件绘制边缘梁；残破发动机降低高度。 | 尚非汽车级弧形一体化外壳；完整开口/损伤形态取决于原版真实零件。 |
| 未知部件 | 任何可感知且非临时伪部件的未知类型依然以小型模块出现，不因贴图缺失过滤整车。 | 复杂船舶、直升机、多节工程车还需定制 profile。 |
| 材质容量 | 共享图集从 1024×1024（256 槽）扩展到 2048×2048（1024 槽），消除一般街景中复杂车型挤掉基础纹理的高风险；槽位仍不足会记警告，车辆留中性几何。 | **不是无限容量多页图集**，极端大量车型和场景下的表现及 FPS 仍需现场测试。 |

## 车辆数据与图块校验

- 本地原版 `data/json/vehicleparts` 解析：350 个带 ID 的车辆零件定义。
- 当前项目不死人贴图资源 `MSX++UnDeadPeopleEdition`：752 个 `vp_*` 资源 ID。
- 对定义 ID 执行与运行时同构的精确/多级继承解析：301 个找到当前包图块（包含初步继承匹配）；其他 ID 由运行态规则按同包图块/安全中性几何降级。
- 测试了 `front_left`、`front_right`、`vertical_left`、`vertical_right`、`horizontal_front` 等方向性变体，确认实际包内存在匹配资源。
- 12 个车身朝向（含 15°、45°）、3 个不同支点、9 个非矩形局部零件位置的刚性矩阵对比，最大距离误差约 `1.33e-15`，未检测到局部零件间随旋转伸缩。
- 源码结构和上述离线检查记录：外部工作区 `qa/validate_vehicle_p2.py`、`qa/vehicle-p2-validation.json`，**这些不是现场游戏截图和驾驶验收**。

## 源码与启动

- `src/fp3d_vehicle_renderer.cpp/.h`：方位、铰链、轮胎、破损/透明体、按原版变体的网格签名。
- `src/fp3d_materials.cpp/.h`：本图块包优先的变体解析、材质键、扩展图集与容量诊断。
- `src/fp3d_snapshot.cpp`：复制真实 `part.variant`。
- `src/fp3d_scene.cpp`：演员/天气后、建筑玻璃前绘制车辆半透明车窗。
- 本轮独立运行目录：`runtime/modern-vehicles-p2`；启动入口：`启动车辆3D-P2验证.cmd` 或当前主入口 `启动3D操作修复验证.cmd`。
- 老 P1 程序仍留在 `runtime/modern-vehicles-p1`。本轮未改 `src/vehicle.cpp`、`src/map.cpp` 或存档结构。
