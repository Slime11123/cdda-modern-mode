# CDDA 3D 车辆 V7：原版车顶损坏拓扑与玻璃透明排序

日期：2026-11-08。接续 [V6 座椅和车壳补缝](FP3D_VEHICLE_V6_CABIN_SHELL_FIX.md)，本阶段直接修改本地 3D 车辆渲染器并制作独立可执行测试版。没有改变原版 CDDA 行驶、碰撞、存档或 2D 界面。

## 背景与根因

用户之前截图显示车身顶部有一片棕黑色、具有纹理的悬浮面，车窗透明层也与红色车身、车顶衔接不佳。核对源代码后发现：

1. V5/V6 渲染屋顶时只要某一纵向 X 行有**任意**完好 `roof` 安装格，就在整车顶宽度上画一片完整板。若右边的屋顶被毁，但左边仍在，旧算法会把实际空洞重新盖住。也会导致改装车辆屋顶截面不符合原版零件拓扑。
2. `draw_closed_silhouette_glass()` 先画挡风玻璃、再画侧窗、最后画后窗，**无论摄像头在哪边**都用固定顺序。半透明混合依赖距离，换方向时可能产生深浅叠加错误。
3. 上述侧窗长度仅为本地 X 的 `±.40`，而上部窗框柱子在约 `±.49`，留有可见的小缝。
4. V6 的**车辆车顶是无纹理的纯色几何体**（`cuboid(...,paint)`）；而项目 `fp3d_scene.cpp` 可以绘制具有当前贴图的**上层地板/建筑天花板**。因此用户照片中的棕色纹理悬浮平面，尚不能不经现场判定就当成汽车顶板误删。不能删除真正的桥梁或房屋上层楼板。

## V7 已直接完成的源码改动

- `src/fp3d_vehicle_renderer.cpp`：关闭车体的屋顶改为二维安装格（X、Z）驱动。只考虑 `roof && !broken_roof` 的真实可用安装格，在每个 Z 列内把连续的 X 段合并为 3D 板块。**缺失/损坏的安装格绝不因相邻列有车顶而被填平**，同时保留顶边收口线。
- `src/fp3d_vehicle_renderer.cpp`：半透明玻璃先生成四顶点平面数组。将摄像头相对整车原点的位置按原版车辆角度逆旋转回车体局部坐标，再按每片窗的中心距离**从远到近稳定排序**，避免原有固定顺序造成叠色错误。
- `src/fp3d_vehicle_renderer.cpp`：侧窗沿纵向从 `±.40` 延伸至 `±.445`，与 `±.49` 的窗框立柱更好衔接，同时保留门窗损坏/开启状态。
- 真实车辆驾驶位置、车轮、碰撞、车漆材质、V6 座椅及车壳连接补丁都继续沿用。没有修改其他正在由 Agent 编辑的 `fp3d_scene.cpp`、`fp3d_snapshot.cpp` 等文件。

- 玻璃从车前/车后观察，远近排序会互换；测试 10 个车辆角度的逆变换计算误差在浮点容许范围内。

- 部署目录：`runtime/modern-vehicles-roof-v7/`，其中 EXE 独立打包，49 个 DLL 用硬链接复用 V6，避免重复占空间。
- `--help` 和 `--jsonverify` 退出码及日志存放 `qa/vehicle-v7-*.log`。以真实日志为准，不能代替游戏实机视觉验收。

## 悬浮深色平面：查因而非误删

到 V7 为止，**尚未通过相同地图位置的上层楼板、车顶贴图 ID 和 GL 绘制调用做现场溯源**。从代码审计看，V6/V7 车辆车顶顶面不采样棕色纹理，因此有理由优先排查地图 `floor_present` / `ceiling_present` 产生的高层贴图面。仍不能断言它一定来自建筑，不应为去掉它而全局禁用 z+1 地板，否则会破坏现有多层建筑。

现场建议：回到同一辆红车旁，先在 V6/V7 对照车顶孔洞和窗玻璃；再移动视角确认棕色面是否随整辆车移动/转弯。如果纹理固定在地图世界坐标，需要检查对应 Z 层的地板/天花板，而不是继续改车顶本体。
