## 2. 新操作设计：不破坏已实现的 WASD/F5/F6

| 输入 | 3D 世界模式 | UI、文本输入、2D 模式 |
|---|---|---|
| WASD | 相机相对移动；长按按原版可接受的连续动作逐次提交 | 菜单归原版；2D 归原版 |
| 移动鼠标 | 转向及俯仰；**只改变观察方向，不推进回合** | UI 鼠标指针 |
| 左键 | 徒手/近战单击攻击；长按按有效动作节奏连续攻击。持枪瞄准时执行原版射击 | UI 左键 |
| 右键 | 持枪进入/退出瞄准（按住）；无枪时可打开情境操作（可配置） | UI 右键 |
| E/长按 E | 默认智能交互 / 环形交互操作 | 菜单 E 由原版或文本框处理 |
| F/长按 F | 对准目标快速拾取 / 附近物品列表 | 菜单 F 不被接管 |
| Tab | 综合生存面板（背包、人物、制作、建造、地图、任务、队友、更多） | 依上下文导航，不接管其他窗口 |
| R | 原版装填手中武器动作 | 菜单 R 仍有效 |
| Shift/Ctrl | 切换原版奔跑/蹲姿状态，**不要只加速度或改相机高** | UI 不拦截 |
| 1–8、滚轮 | 快捷栏选择及原版穿戴/持握/使用动作 | 菜单自行滚动 |
| Q | 快捷行动轮盘（投掷/特殊行动/拖拽） | UI 按键按原版处理 |
| M | 原版大地图 + 新的目的地标记交互 | 2D 原绑定不变 |
| Alt（按住） | 展开全部生存状态，松开折叠 | 不劫持 Alt+Tab |
| Space | 执行原版等待动作（时长设定明确），不可空转模拟 | 菜单 Space 保留选择语义 |
| F5 / F6 | 2D/3D 模式切换 / 两套操作设置 | 与现有行为完全相同 |
| Esc | 退出面板/轮盘，或进入原版暂停菜单 | 依原版上下文 |

**所有新按键先在 `FP3D` 类别注册，不硬编码覆盖 SDL 的全局快捷键。** 长按阈值建议初值 250ms，可设置；计时只用于输入分类，不能自己推进游戏回合。鼠标连续点击与长按不得双重触发。

## 3. 推荐新增的架构：原有路径不重写

```text
SDL2 原生事件
 ├─ 现有 fp3d_compositor::process_event （F5、鼠标视角、焦点、生命周期）
 └─ 3D 世界输入（仅 DEFAULTMODE + captures_game_input）
     ├─ fp3d_input （FP3D 配置、短按长按、命令解析）
     ├─ fp3d_targeting （只读准星检测：相机 + 已许可可见场景）
     └─ fp3d_interaction （结构化“交互意图”，可带格子/目标类型）
           │
           ▼ 游戏主线程重验：LOS、距离、权限、安全模式、有效对象、物品位置
           │
     原版 game::handle_action / game::do_regular_action / 受控原版目标接口
           │
           ├─ 原版行动点、时间、命中、装填、口袋、碰撞、AI
           └─ 原有游戏世界状态
           │
           ▼
  fp3d_snapshot::capture（展示快照） + fp3d_compositor + fp3d_scene
           └─ fp3d_hud/现代 UI（仅表现层）
```

新模块建议（名称供 Codex 定稿，先查有没有重名）：`src/fp3d_targeting.h/.cpp`、`src/fp3d_interaction.h/.cpp`、`src/fp3d_hud.h/.cpp`、`src/fp3d_modern_ui.h/.cpp`。不要一次性建立全套空文件；按阶段按需增加并接入 CMake。`ENABLE_FP3D=OFF` 和无 TILES 场景不能引用其符号。

### 3.1 准星选择不是游戏判定

- 以当前 3D 相机位置/yaw/pitch 做只读有限距离射线检测，按优先级选择可见生物、门窗、家具、物品、车辆、NPC；跨层时使用真实 3D 高度而非强制 z=玩家层。
- UI 命中可借助**经过可见性/记忆过滤**的 `scene_snapshot`，但不能根据仅“记忆过”的格子允许战斗/拾取，也不能从快照外推不可见敌人。
- 用户按 E/F/攻击后在游戏主线程重新取得目标格和对象，并根据原版 `you.sees`、`here.inbounds`、距离、状态、权限验证；目标移动、隐藏、死亡、相机更改后立即失效。
- 最好让目标识别输出例如 `{kind, absolute_tile, candidate_id, camera_generation}`，严禁长期持有 `map`/Creature 裸指针或跨世界复用目标。
- 第一期仅做准星前方 1 格交互与可视的附近物品；后续再扩展可靠的近距离 3D 射线命中。
- 射线穿墙、楼板阻挡、门窗高度、透明植物与 LOS 规则要单独测试；GPU depth test 不是游戏权限检查。

### 3.2 把普通 action 和带目标意图区分

`fp3d_input::resolve()` 当前只返回字符串，可继续处理移动/打开菜单/装填等**不需要目标参数**的原版操作；精确 E/F/射击应走结构化意图与受控执行桥接。

**不要**通过向 SDL 注入伪按键、从渲染线程直接调用 `game::open`、手动扣行动点、或绕过 `do_regular_action` 让功能“看起来可用”。

若某个原版调用只弹出方向选择器，优先：
1. 复用原版已有带坐标参数的 API；
2. 若没有，最小侵入地抽取“已验证目标 + 原版操作”的公共函数，让传统键盘路径与 3D 路径共用；
3. 最后才考虑受控的 UI 方向输入适配，不复制整段游戏规则。

所有操作应统一检查：动画/按键事件去重、点击边缘触发、原版合法性、目标距离、被攻击反击/安全模式、武器失效、弹药、取消/失败不误扣回合，以及特殊动作的原版时间消耗。

## 4. 功能实施细节

### 4.1 P5 第一优先：E/F + 鼠标战斗构成生存闭环

**E**：对准可交互目标 → 显示“E 开门 / 交谈 / 查看 / 进入车辆”；长按 E 环形菜单只列出当前合法选项。开门目前调用 `open()` 而非定点函数，需要封装后才保证准星目标不串位。门关闭可以研究已有 `doors::close_door(here,player,*mouse_target)` 路径，但不得假定所有类型门共用此接口。

**F**：单击拾取准星所指、距离可达、当前可见的物品；目标没有有效内容时给提示，不随意拾取身后物品。长按 F 显示当前角色能接触的“附近物品/容器”面板；排序、批量拾取、拖拽后仍执行原版重量/体积/口袋检查；取消移动不消耗错误的时间。

**战斗**：短按近战先确定目标，再调用原版近战合法流程；长按左键必须逐个经原版动作许可与结算，不允许独立实时时钟每隔 N ms 硬塞多次攻击。枪械右键进入瞄准 UI，准星位置只是目标指定；枪械命中、技能、射速、瞄准时间、后坐力、开火模式交给原版 `fire()`/射击逻辑。建议先复用原版瞄准 UI 作为过渡，之后再做 HUD 化瞄准；长按左键不能绕过原版射击模式/枪械操作。

**回合制不变量**：鼠标转头 1000 次、静止 HUD 刷新、打开关闭面板、取消轮盘都不能改变 `calendar::turn`、角色行动点、饥渴状态或怪物行为；真实攻击/移动/治疗与原版同等耗时。

### 4.2 Tab 综合生存菜单：按用户参考截图重设计（2026-10-28 新增，强制需求）

**UI 设计基准**：用户提供的暗色半透明生存背包界面截图。目标是**真正可视化、鼠标可操作的综合菜单**，而不只是顶端一排按钮跳转原版文本窗口。借鉴截图的**顶部导航 + 左侧竖向分类 + 左中右三栏物品管理 + 方格物品图标 + 搜索筛选 + 悬停详情 + 底部操作提示**。无需照搬游戏的商标、贴图或具体配色资产；全部使用项目已授权/合法的 UI 与图块素材。

#### 4.2.1 页面层级与全局交互

- **Tab**：从 3D 世界打开/关闭统一菜单；ESC 关闭或返回上一级；菜单状态屏蔽 WASD 移动、开枪、拾取及 3D 射线交互；释放相对鼠标，显示正常系统光标；回到世界恢复相对鼠标。
- **顶部横向一级导航**：`背包 Inventory`、`人物/健康`、`制作`、`建造`、`地图`、`任务`、`队友`、`更多`。位置与截图左上方“VIEWPOINT / INVENTORY”同级导航的视觉语言类似；默认打开上次使用的页面，首次打开默认背包。右上角为关闭（X）。
- **左侧窄竖栏二级导航**：针对当前一级页显示相关图标子页；背包默认“装备与物品”，其余子页可为武器/衣物/身体状态/能力/配方收藏等。每个图标有悬浮名称及选中态；禁止使用只有图标却没有提示的不可理解按钮。
- **页面主体**：深色半透明面板覆盖 3D 画面的大部分区域，保留背景画面可见；文本/物品对比度优先于透明美观；边框与分区细线、选中强调色、容量条与耐久条参照截图。UI 设计以 1920×1080 及 16:9 为首要基准；1080p 上无需水平滚动才能看见关键面板。
- **不要**把 2D 原版操作页直接长期覆盖在新画面上；允许作为逐步交付期间的过渡“跳转/弹窗”，但最后背包页必须原生呈现下述三栏布局并可直接转移物品。其他页可以分期替换。
- 进入 Tab 后**不能自动推进游戏世界时间**；停留、搜索、滚动、悬停、筛选、换页、取消拖动不执行回合。只有真实应用物品、穿戴/脱下、拾取/转移、使用/制作等提交动作按照原版耗时结算；菜单打开时完成耗时行为须遵从原版活动/敌人行动，不能一边冻结世界一边免费搬运或制作。

具体布局建议：**左装备区域 30% / 中自有物品 35% / 右附近物品 35%**（包含二级窄图标栏，按实际窗口弹性调整）。面板分别滚动，不要整个 UI 一起滚动；保留顶部导航和底部提示固定位置。

**左栏“装备 Gear”**：
- 显示主手/副手/双手，以及头、眼、脸、颈、躯干多层、手臂、手套、腿、袜、鞋、背、腰带、附挂等，按 CDDA 实际装备/覆盖与穿戴层语义组织，不照抄截图的所有固定槽并强行限制多层穿戴。
- 每格显示来自当前图块包的物品图标、名称悬浮提示、耐久/状态小条；空槽显示部位名称；受伤部位可高亮并通往“人物/健康”页。
- 装备格可接受合法的拖拽物品；装备/卸下/切换手持物必须由原版穿戴与持握逻辑判定，显示覆盖冲突、阻碍、重量及防护提示。
- 允许一个部位存在多件不同穿戴层的物品；必要时点击装备槽展开层叠清单，**不要采用会丢失 CDDA 装备层次的一格一件假模型**。

**中栏“You / 我的物品”**：
- 顶部搜索框、排序下拉及分类筛选条（全部、武器、弹药、食物、医疗、衣物、背包、工具，可水平滚动）。
- 第一层按来源容器分组：当前背包、衣物口袋、腰包、附挂容器、手持、嵌套袋等；展开/折叠显示真实 pocket 容量（体积/重量/长度等，按原版当前容器限制）。
- 每组以紧凑**方格图标网格**展示，图标右上角数量/充能、底边耐久/状态条；点击选中，悬停显示简略名称，右键显示操作，支持图标与文字列表切换但默认网格。
- 搜索命中容器内的物品时显示其归属链（例如“背包 > 工具袋 > 急救包”），默认搜索应覆盖可达的嵌套内容，但不泄露封闭/不可访问容器内部。
- 装入/取出时必须按真实容器 `item_location` + pocket 数据寻址；容量条**不是**简单的虚构“20 格背包容量”。

**右栏“Nearby / 附近物品”**：
- 以**实际来源**分组：脚下地面、邻近合法范围地面、打开的冰箱/柜子/箱子、车辆货箱等；每组清楚标注名称、距离、所在 z 层与其可用容量信息。
- 只列出角色按原版视线/接近/容器访问权限**当前可获知**的物品：不可见隔墙、隔楼板、未打开的封闭容器内部不预览；必要时先执行合法检查/开启动作。
- 支持只显示指定来源、搜索物品、分组折叠、排序、物品网格以及从右向中拖拽/双击拾取；右侧多个附近容器彼此独立滚动/折叠。
- 物品在地面/容器/车辆间的转移，必须复用原版 `pickup`、`advanced inventory`、`item_location` 等逻辑。允许取消和失败反馈；**禁止直接修改地图物品 vector 或拷贝 item 以模拟移动**。

**交互规则**：
1. 左键选中；双击默认执行“最合理且安全”的操作（建议默认**打开详情**或可配置的双击拾取/使用；避免双击误食、误丢危险物品）；右键打开物品情境菜单（查看、使用、穿戴/脱下、持握、装填、放入/取出、丢弃、拆解、收藏/快捷栏等，仅显示合法命令）。
2. 支持单件拖拽、多选/批量、源到目标口袋、整组“全部拿走”或“放入容器”。批量移动需逐项按原版合法性和耗时判定，给出成功/失败清单；当多个口袋可装时弹出目标口袋选择或使用原版可接受的自动装袋策略。
3. 鼠标悬停详情卡显示：物品名称、重量、体积、堆叠数量、容器位置、状态/损坏、武器伤害/弹药、食品腐败/温度/营养等**原版可公开描述的属性**；不要直接复制截图里的不属于 CDDA 的数值面板。
4. 顶部排序与分类筛选应作用于各自物品区域（或设置明确的“同时筛选左右”开关）；检索不会触发搬运动作；中文输入法输入、搜索框焦点及热键冲突必须测试。
5. 底栏固定显示控制提示，并随选中物品变化（鼠标手势、Shift 批量、R 拿取/装填等）；可在设置中查看完整快捷键，不必完全沿用截图的键位。

#### 4.2.3 统一菜单其他页也要保持同一视觉骨架

- **人物/健康**：左身体轮廓/部位状态，中间基本属性/技能/疼痛/疲劳/变异/仿生模块，右侧状态详情与操作；避免堆砌原版文字弹窗。
- **制作**：左配方分类，中间配方卡片网格、搜索/收藏，右侧材料清单/来源、技能与耗时、数量设置和制作按钮。
- **建造**：左建筑分类，中间建筑选项，右侧材料与施工条件；确认后关闭菜单进入**半透明 3D 蓝图放置**，重新校验合法格子。
- **地图**：地图居中占主要面积，左右侧栏为标记、目标和路线设置；仍允许按 M 直接打开。
- **任务/队友**：左列表、中详情、右操作命令；仅展示原版可访问的任务、NPC 与队友状态。
- **更多**：车辆、区域管理、技能/能力、日志与设置放在统一页面体系，不恢复大量孤立字母热键。
- 所有一级导航复用一套布局、字体、边距、按钮、滚动与鼠标操作规范。不能仅背包页现代化，其他页突然变成无法鼠标交互的旧界面；允许在分阶段实施时标明“原版兼容入口”。

#### 4.2.4 与现有 CDDA 0.I-1 框架衔接

- 首先确认当前源码中 **ImGui/SDL UI 的可复用组件与事件路由**，为 Tab 菜单创建专属输入上下文；保持同一 SDL2 窗口、单一 GL 上下文及现有 `fp3d_compositor` 生命周期。不在 GL 渲染回调里直接调用任何拾取/穿戴/使用行为。
- 进入菜单必须调用/兼容现有 `fp3d_compositor::set_input_context` 与 `sync_mouse()`：释放相对鼠标，避免 `process_event` 吞掉 UI 鼠标事件；菜单关闭恢复。鼠标滚轮优先滚动当前悬停栏而非切换 3D 快捷栏。
- 使用**只读的背包/装备/附近物品视图模型**构建卡片与图标，再将点击/拖拽转换为结构化操作请求；提交前在游戏主线程重新定位并验证 `item_location`、源/目标 pocket、数量与容器可访问性。物品变化后刷新对应列表，避免悬空引用、双重搬运与并发 UI 更新。
- 图标先复用已有图块包/ `fp3d_materials` 的素材解析思路，但**不要**把 3D 地形/手持物品 atlas 当成永不失效的背包 UI 图标缓存；图块包热切换时重建缓存，未知物品显示统一占位图。
- 可配置 UI 缩放（至少 100%、125%、150%）；在 1280×720 时让右栏折叠为可切换抽屉/标签，装备区压缩，保持完整可操作；1080p 三栏完整呈现。
- 原版背包/高级物品管理的**原生入口仍保留**作兼容和验证基准；新背包不能破坏原版 2D 操作及存档兼容。

#### 4.2.5 Tab 菜单分阶段交付（细化 P5.4）

1. **UI-S1：视觉骨架**：实现顶部一级导航、左侧分类图标、三栏占位、深色半透明主题、右上角关闭、响应式缩放、可靠焦点管理；可只读展示真实人物数据。**这一阶段不能冒称完整背包已实现**。

#### 4.2.7 HUD（世界视角）与 Tab 菜单分离

HUD 仍采用已确认的“动态混合式”：在 3D 地图视口内显示准星、关键生命/耐力与异常状态、快捷栏、弹药和姿态；战斗扩展提示，按住 Alt 展开完整状态。**不要把截图中的完整背包三栏放在正常探索时的 HUD 上。** 现有右侧原版侧栏暂保留兼容开关，逐步消除重复信息。HUD 状态来自原版角色，不改存档。

### 4.3 车辆控制

原版 `ACTION_CONTROL_VEHICLE` 入口已经存在；驾驶时 **WASD 不应再被无条件解析成徒步行动**。引入“步行 / 已控制车辆 / 乘客 / 骑乘”的模式判别；在车辆控制状态下将键映射为原版转向、油门/刹车/手刹等真正支持的车辆指令，确认原版驾驶输入接口后实现。

3D 车镜头/车身只做视觉插值，必须以确认后的速度和坐标为准；撞墙/高速位移/翻车时立即重置插值。不能在游戏静止时偷偷运行驾驶模拟以追求视觉实时感。

### 4.4 建造、NPC、地图

- 建造：Tab 选择原版 recipe/建造条目 → 准星定位到合法格 → 3D 半透明模型（现有 `floor_height`/多层坐标一致）→ 点击确认 → **原版建造活动**处理材料、工具、时间及成功失败。
- NPC：E 对话，长按 E 打开“交易/招募/跟随/守卫”等仅在原版合法的指令；队友页先调用原版菜单和操作，不引入平行的 NPC AI。
- 地图：M 使用原版 overmap，添加目的地标记和可关闭方向提示；自动走路沿用 `avatar::get_next_auto_move_direction()` / `has_destination()` 体系，遇敌、安全模式、道路被堵、场景失效就停止；禁止自建无回合免费瞬移导航。
- 3D 建筑多层进行中：交互与射线必须知道 z；不能只让相机看见二楼而允许隔楼板拾取或对话。
