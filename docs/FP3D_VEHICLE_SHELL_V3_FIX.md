# 车辆 3D 连续车身 V3 — 2D 红车 / 3D 裸露框架修复

日期：2026-11-08。根据用户实机截图（2D 中一辆红色破损轿车；3D 中车架外露、无完整车壳、车窗像高墙，内部设备如办公桌般排列）检查项目源代码和不死人贴图包。

## 根因（已在真实源码和原版数据定义中证实）

1. `fp3d_snapshot::capture()` 旧的车辆角色分类顺序将 `VPFLAG_WINDOW` 排在车门前。原版 `door` 同时带 `DOOR`、`WINDOW`、`BOARDABLE` 等 flag，于是车门被错误当成高耸玻璃窗；之前 `role::window` 每个零件都是独立 3D 方框。
2. 旧代码把 `BOARDABLE` 等同 `SEAT`。原版 `trunk` 同时有 `BOARDABLE`、`CARGO`，导致后备厢显示成座椅。
3. `frame`、`roof`、`door`、`halfboard`、`windshield`、`dashboard`、`controls` 等本来堆叠在同一车辆挂点上。旧 `one_part()` 对每个真实零件都独立绘制一个灰色长方体，没有共用的底盘/车壳外轮廓。
4. 旧材质只是把选中图块包的 `vp_*` 贴到方盒顶部，侧面始终是固定蓝灰色，与当前不死人包的红色车漆风格不符。

## V3 修复后的规则

| 项目 | 修复 |
|---|---|
| 原版角色识别 | 按 WHEEL / ROOF / DOOR+OPENABLE / 原版车身板件 / WINDOW / ARMOR / SEAT / ENGINE / LIGHT / CARGO / FRAME 等优先级分类；车门拥有独立 `glazed_door`，不再变为风挡玻璃。 |
| 真实车身几何 | 将同一车 mount 的零件聚合为 shell cell，仅当存在足够原生车架、车顶、车门/围板/窗时生成闭合车身。按相邻安装格的实际外边缘放置连续下围板、底盘、机舱盖和车顶。 |
| 破损状态 | 破损车身板只保留较矮、较短的撕裂侧围；破损机舱盖不恢复整片顶面；缺失零件不凭空补出车架或车顶。 |
| 实际车漆 | `fp3d_materials::prepare` 从**当前选择的贴图包**生成的车辆零件 SDL 图集按需读取屋顶、门、车身板件的像素，从彩色像素中推断主色；写进车辆自己的 mesh/display list；切换图块包/材质重置时清除该颜色缓存。 |
| 挡风玻璃 | `windshield` 生成倾斜薄玻璃片和窄边框，坐标绑定到真实挂点和整车根变换，不再伸出数个 2 米高竖立玻璃墙。 |
| 车门 | 原版 `DOOR` 型组件改为彩色下门板、上门框及仅在未损坏/关闭时的透明门玻璃；开关沿局部铰链旋转。 |
| 设备与座椅 | 收纳在真实车壳内的仪表、喇叭、工具等不再单独作为路面上方的方块；真实座椅仍留在车内，通过透明窗可见。 |
| 非轿车 | 对开放式自行车、手推车、临时车架仍保留管状车架和各自可见零件，绝不因为“有车架”就套用轿车密闭外壳。 |
| 原版数据保护 | 不改 `vehicle.cpp`、`map.cpp`、原版移动格、零件挂点、碰撞、车辆物理和存档。 |

## 真实贴图素材核对

直接读取本机用户已安装的 `MSX++UnDeadPeopleEdition` 实际 PNG 与 `tile_config.json`，不用猜颜色：抽样得到 `vp_roof` 主色 RGB ≈ (101,40,39)、`vp_halfboard` ≈ (81,28,27)、`vp_door` ≈ (86,27,26)、`vp_door_front_left` ≈ (84,25,24)。这是游戏中红色车身的真实来源，材料读取逻辑不依赖固定文件名。

原版 `data/json/vehicles/cars.json` 也验证了真实车辆的同一安装格多零件堆叠：`4x4_car_abstract` 有 29 个安装格 / 81 个真实定义零件（24 个带多零件），`beetle` 有 16 个安装格 / 56 个零件（全部安装格都是堆叠）。新车壳按安装格合并，旧版则把这些零件逐个变成方盒。

## 文件

- `src/fp3d_snapshot.cpp`：分类优先级，真实窗门标记。
- `src/fp3d_vehicle_renderer.h/.cpp`：新增车身板类型、连续实体车壳/损坏侧围、倾斜挡风、门窗分离、内部设备遮蔽。
- `src/fp3d_materials.h/.cpp`：当前图块包车漆像素采样及缓存清除。
- 构建目录 `build/0i1`；独立运行目录 `runtime/modern-vehicles-shell-v3`（此前 P1/P2 保留）。
- 测试脚本 `qa/validate_vehicle_shell_v3.py`，结构与原版 JSON/PNG 校验结果 `qa/vehicle-shell-v3-regression.json`。

## 验收边界

已完成 C++ 编译与链接、对原版车辆 JSON 及当前不死人图块原像素的离线检查。新打包 EXE 的 `--help` 和 `--jsonverify` 结果单独记录在 QA 日志。

**这不等于四方向、实际车门开合、碰撞偏差、普通轿车和事故残骸均已在游戏实机通过视觉验收。** 这仍是程序化格架车体而非为每一类汽车制作的精细 OBJ/FBX 车模。后续按计划继续调驾驶镜头、准星交互、轮胎方向与车辆模型细化。
