# 3D 移动开销检查（2026-11-08）

## 本轮改动

- 3D 主画面刷新直接使用 `prepare_view` 已准备的玩家层缓存，避免先走原版路径、再重复生成玩家层光照和可见性缓存。2D 继续走原版路径。
- 地图快照只读取原版遮挡、距离、摄像头和瞄准门限，不再为每个可见地块计算最终没有使用的亮度及不透明墙体光照象限。
- 邻接空气检查只对需要补足外立面的不可见上层地块执行；先检查已有可见性标记，再查询室内外状态。特殊塔楼仍保留原有表面白名单、距离和瞄准限制。
- 家具模型与 looks_like 链在一次快照中按家具 ID 复用，下一次快照重新查询；地块仍独立保存模型数据，接电家电仍使用原版部件状态。

没有降低渲染距离、楼层范围或材质质量。工作区原先已有反射蒙版、玻璃/容器/精灵索引和车辆剔除方面的未提交改动，本轮保留，未纳入本次源码提交。本地构建包含当前工作树中的这些既有改动。

## 对照结果及范围

使用同一随机种子 424242、同一连续 12 步移动场景、6 名 NPC。修改前两次平均快照耗时分别为 **15.32 ms、16.20 ms**，最终修改后为 **13.87 ms**，对应约 **9%—14%** 的下降。最终 12 步的地块数、精灵数与修改前逐步一致。该数字只代表 CPU 准备 3D 场景数据的耗时，不能换算为整场游戏 FPS；原版模拟、可见性缓存准备和 GPU 光影不包含在这个数字中。

相关的移动、瞄准/墙体遮挡、白天夜晚/烟雾/失明/透视能力/摄像头、上下楼层隐私、塔楼外观和接电烤箱检查：**7 用例、198 断言通过**。新增瞄准检查逐格对照原版 `apparent_light_helper` 的遮挡结果。修正了既有测试中两个缺少括号的 Catch 表达式，使专项检查可编译。

扩展家具检查另有床上石头被床模型优先命中的 **2 个断言失败**。临时恢复本轮修改前的快照代码再次对照，仍在相同位置失败；随后恢复优化代码并构建通过。本轮没有修改床模型或准星命中算法，不将该问题标记为已解决。

证据位于工作区 `qa/0i1/movement-20261108/`：`before/moving-capture.csv`、`control/moving-capture.csv`、`verified/moving-capture.csv`、`summary.json`、`verified.log` 和 `control.log`。未重跑全套游戏或图形回归。

## 后续值得优先处理的点

1. `prepare_view` 逐层调用 `build_map_cache`；每次都会经过全楼层公共缓存检查。后续可将公共缓存准备和逐层光照生成分开，须保留跨层生物隐藏、光照和摄像头行为。
2. 城市内每回合重新生成整份地块快照、散列表和区块签名。增量更新应跟随原版地图/可见性失效信息，不能仅按玩家位置缓存，否则开关门、血迹、掉落物和破坏建筑会延迟显示。
3. 在玩家卡顿的城市存档中分别测量原版回合模拟、地图缓存、CPU 场景绘制和 GPU 后处理，再选择下一项优化；开放地面这组数据不足以说明城市卡顿已经完全消除。
